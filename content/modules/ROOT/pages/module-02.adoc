= Step 2 Vulnerability & Patch Management

Before you harden _how_ a system is configured, you deal with _what software_ is on it.
Unpatched packages with known CVEs are the most common way systems get compromised. In this
module, you will walk through how to enumerate outstanding security vulnerabilities on a RHEL 10
host and apply the security patches.

[IMPORTANT]
====
*Read-Only Walkthrough* → Do *not* run these commands in the terminal. This lab sandbox uses an
isolated environment without live Red Hat CDN errata metadata, so `dnf updateinfo` will return
empty or fail to reach a repository. Review the commands and sample outputs below to see how this
workflow looks on a subscribed RHEL 10 host before moving to the next module.
====

[NOTE]
====
*Why not an OpenSCAP OVAL scan?*

On older RHEL you might have scanned for CVEs using an OVAL feed. Red Hat put the OVAL v2 feed
into maintenance mode and does *not* publish OVAL data for RHEL 10 — the security data now ships
as CSAF/VEX. On RHEL 10 the supported way to enumerate CVEs and errata on a running host is the
built-in `dnf updateinfo`, which is backed by the repository `updateinfo` metadata.
====

== Step 2.1 — See the big picture

Ask `dnf` for a summary of outstanding advisories, grouped by type and severity:

[source,bash]
----
sudo dnf updateinfo summary
----

.Example output
[source,text]
----
Updating Subscription Management repositories.
Last metadata expiration check: 0:14:22 ago on Tue 24 Nov 2026 09:15:02 AM UTC.
Updates Information Summary: available
    4 Security notice(s)
        1 Critical Security notice(s)
        2 Important Security notice(s)
        1 Moderate Security notice(s)
    12 Bugfix notice(s)
    2 Enhancement notice(s)
----

The *Security* line is what matters most — it tells you how many security advisories apply to
packages currently installed on this box.

== Step 2.2 — List outstanding security advisories (RHSAs)

Now list the individual security advisories (RHSAs) and the packages they fix:

[source,bash]
----
sudo dnf updateinfo list --security
----

.Example output
[source,text]
----
RHSA-2026:1842 Critical/Sec.  openssl-libs-1:3.2.2-16.el10_0.x86_64
RHSA-2026:1905 Important/Sec. sudo-1.9.15p5-8.el10_0.x86_64
RHSA-2026:1911 Important/Sec. glibc-2.39-37.el10_0.x86_64
RHSA-2026:1940 Moderate/Sec.  curl-8.9.1-5.el10_0.x86_64
----

== Step 2.3 — List outstanding security CVE IDs

The same gap can be viewed as the CVE IDs it closes — handy when an auditor hands you a list of
CVEs to confirm:

[source,bash]
----
sudo dnf updateinfo list --cves
----

.Example output
[source,text]
----
CVE-2026-24109 Critical/Sec.  openssl-libs-1:3.2.2-16.el10_0.x86_64
CVE-2026-21884 Important/Sec. sudo-1.9.15p5-8.el10_0.x86_64
CVE-2026-22910 Important/Sec. glibc-2.39-37.el10_0.x86_64
CVE-2026-23004 Moderate/Sec.  curl-8.9.1-5.el10_0.x86_64
----

== Step 2.4 — Inspect the detail

Pull the full description, severity, and CVE list for the outstanding security advisories:

[source,bash]
----
sudo dnf updateinfo info --security
----

.Example output (abbreviated)
[source,text]
----
===============================================================================
  Critical: openssl security update
===============================================================================
  Update ID : RHSA-2026:1842
       Type : security
    Updated : 2026-11-18 14:22:09 UTC
       CVEs : CVE-2026-24109
Description : OpenSSL is a toolkit that implements the Secure Sockets Layer
            : (SSL) and Transport Layer Security (TLS) protocols, as well as a
            : full-strength general-purpose cryptography library.
            :
            : Security Fix(es):
            : * openssl: buffer overflow in X.509 certificate verification
            :   (CVE-2026-24109)
   Severity : Critical
----

[quote, Manager Bill]
____
"CVEs? Just delete them. Can't you `rm` a CVE?"
____

[quote, Sysadmin Grace]
____
"No, Bill. You _patch_ the package that the CVE lives in. `dnf` already knows exactly which

____

== Step 2.5 — Apply the security patches

Install *only* the security-relevant updates in a single transaction (leaving non-security bugfixes
and enhancements untouched):

[source,bash]
----
sudo dnf -y --security update
----

.Example output (abbreviated)

== Step 2.6 — Verify the gap is closed

Re-run the security list. It now returns nothing — every outstanding security advisory has been
applied:

[source,bash]
----
sudo dnf updateinfo list --security
----

.Example output
[source,text]
----
Updating Subscription Management repositories.
Last metadata expiration check: 0:00:08 ago on Tue 24 Nov 2026 09:31:14 AM UTC.
----

[NOTE]
====
Patch management closes _known_ vulnerabilities in your software. *Compliance hardening* — the
rest of this lab — is the complementary half: it makes sure the system is _configured_ securely
even when every package is up to date. You need both.
====

Once you have reviewed how `dnf updateinfo` identifies and closes known CVEs, continue to the
next module to start your first compliance audit on *Box 1*.
